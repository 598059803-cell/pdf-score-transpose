# 环境与识谱校对

## 本机工具配置

只连接已有或用户授权配置的工具，不假定固定盘符、用户名或安装位置。使用 `config.local.toml` 或 `SCOREFLOW_CONFIG` 指向私有 TOML。工具参数用数组传递，不拼接 shell 命令。

`tools.audiveris_home` 适用于含 `runtime/bin/java` 和 `app/audiveris.jar` 的 Audiveris 应用目录。它绕过 GUI 启动器，使用应用自带 Java。否则可配置 Audiveris 可执行文件或完整命令数组。不要用过旧的系统 Java 代替应用所需运行时。

Windows 上调用 GUI 子系统的命令行程序时必须等待其进程退出。脚本采用 `subprocess.run`；PowerShell 手工调用 MuseScore 时用 `Start-Process -Wait`，不能根据启动命令已经返回就宣布文件生成成功。

Audiveris 的中英文文本识别需安装对应语言数据，`--languages chi_sim+eng` 只选择语言，不会下载数据。按 [Audiveris 语言说明](https://audiveris.github.io/audiveris/_pages/guides/main/languages/) 放置其支持的 Tesseract 数据；Windows 通常位于 `%APPDATA%/AudiverisLtd/audiveris/config/tessdata`。检查启动日志实际列出的已安装语言，不只检查环境变量。

## PDF 输入

- 默认把最长边设为 3500 像素。先看原页是否矢量谱、扫描页、歪斜、低对比度或带批注。
- `--threshold 150` 仅是可选的灰度二值化参数。某些浅水印会消失，但灰色音符、细线或表情记号也可能丢失；必须比较处理前后谱页再采用。
- 不为转换改写原 PDF。真正需要打开口令时提供可读来源；已经可显示且用户授权处理的文件可以进入本地识谱。

## 物理谱表与逻辑声部

Audiveris 可把全称/缩写或识别错误当成不同声部，导致导出大量含占位休止符的声部。不要只按“有音符最多”选择一个声部，其他页面可能落在另一个别名中。

`repair-parts` 读取 `.omr` 的 `book.xml`、每页物理系统和小节堆栈，按上下顺序连接逻辑别名，并将各来源的时值单位归一化。它只处理物理谱表结构一致且小节数完全吻合的情况。

若空声部隐藏、乐器中途加入、跨乐章结构变化或多小节休止破坏了对应关系，工具会停止。查看原图与 Audiveris 项目，再明确映射；不能用补休止符来掩盖丢页或错配。

## 音乐校对

先检查结构与代表性小节，再定位报告中的异常：

- 页首/页末与小节连续性；钢琴仍为同一乐器的两条谱表；鼓组没有被升降调。
- 调号与实际音高同时正确。不能用修改调号来掩盖识谱中遗漏的升降音。
- 首个旋律、跨八度音、临时升降号、和弦及末尾音实际移动了指定音程。
- 节奏报告保留不满拍/超拍的原始读数。震音、三连音、延音和多声部可能被误读，按原谱修正后重查，不自动拉伸时值。
- 中文歌词检查漏字、错字、多个字粘在一个音符、与连音延长部分错位等问题。
- 打击乐检查叉形/圈叉符头、独立高音位符头和同节奏和弦是否漏识。单首曲目的图像匹配模板不能直接用于另一首谱。

如使用 RapidOCR 额外读歌词，应只处理文字条带，再按文字位置与音符对应检查。其检测器默认短边缩放；细长歌词条带用 `det_limit_type="max"` 配合合理最长边，避免把窄条放大到极大画布。不要把重新识别出的文字未经对齐检查直接覆盖整首歌词。

## 输出状态

`transposed_needs_proofreading` 表示确定性的移调完成，不代表识谱正确。报告保留实际检查项目。保留 `.omr` 供后续修订，保留确认过的原调 MusicXML 供重做移调。每次更改从原调母版产生新输出。

生成 PDF 后渲染并查看页面，检查标题、歌词、谱表、连线和分页。命令退出码、PDF 存在或 `.sib` 签名均不能代替音乐和页面检查。
